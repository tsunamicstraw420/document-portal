Custom AI Agents — A Learning Path for Eddie

A self-paced curriculum that takes you from "what is an agent?" to designing and building custom agents for your own projects. Built for a no-code learner who wants real conceptual depth: you'll understand the theory, master the no-code tools you can actually build with today, get fluent in the Claude/Cowork ecosystem, and gain enough literacy in the Python frameworks to direct an AI or a developer without writing the code yourself.

Last updated: August 2026 (resources re-checked against live sources 14 Aug 2026). The agent field moves fast — treat specific tool details as "true this month" and re-check with the companion Agents_Research_Prompt.md every couple of months.

How to use this path

  • Pace: ~6 weeks at 3–5 hours/week, or compress to 3 weeks if you go full-time. Each phase has an outcome and a small hands-on "build."
  • Learn by shipping. Every phase ends with something you make, not just watch. The goal is a working agent for one of your projects by the end.
  • Don't skip Phase 1. The vocabulary makes everything after it click.
  • Use the portal's built-in learning log — under every phase in the portal there's a box where you write, in your own words, the answer to that phase's "you should be able to explain" checkpoint. It saves as you type. Teaching it back is how it sticks.

The north-star mental model

An agent is just a model + instructions + tools + memory + a loop. It reads a goal, decides on a next step, uses a tool, looks at the result, and repeats until done. Everything else in this course is a variation on that one loop. Hold onto it.

Phase 0 — Orientation (½ week)

Outcome: You know what you're aiming at and have your toolkit ready.

  • Read Anthropic's essay "Building Effective Agents" (anthropic.com/engineering/building-effective-agents) once, lightly — it's dated Dec 2024, so read it for the durable concepts; Anthropic itself notes the tooling has changed since. Pair it with the current "Building agents with the Claude Agent SDK" (2025). Don't worry about understanding all of it — it becomes your re-read anchor later.
  • Set up free accounts you'll use: Claude (you have Cowork), a no-code tool (start with n8n free/self-host or Zapier), and optionally ChatGPT for a second opinion.
  • Your learning log and project list live in the portal now: write each phase's checkpoint answer in the log box under that phase, and add the 2–4 projects you want agents to help with on the My Projects tab (it starts with the podcast). You'll map agents onto these in Phase 7.

You should be able to explain: why "agent" is different from "a really good prompt."

Phase 1 — Foundations & vocabulary (1 week)

Outcome: You can define an agent, describe its loop, and understand every term you'll hear.

Core concepts to nail:

  • Agent vs. chatbot vs. workflow vs. single prompt. A chatbot answers; a workflow follows fixed steps; an agent decides its own steps toward a goal using tools.
  • The agent loop: perceive → reason/plan → act (use a tool) → observe → repeat. Trace it through one everyday example (e.g. "research a topic and write a summary").
  • The five building blocks: the model (the brain), instructions (the system prompt/role), tools (its hands), memory (what it remembers), and the control loop (what keeps it going).
  • Key terms, one sentence each: tool use / function calling, ReAct, context window, RAG, MCP, orchestration, guardrails, evals, human-in-the-loop, token.

Do this course (the best free starting point):

  • Hugging Face AI Agents Course — vendor-neutral, four units from "what is an agent" through building simple ones. Just do Unit 1 now; you'll return for the rest. (huggingface.co/learn)

Build: Write a one-page, plain-English explainer of "how an AI agent works" in your learning log — as if teaching a friend. This is your comprehension test.

You should be able to explain: the agent loop and the five building blocks without notes.

Phase 2 — Build your first agent (no-code) (1 week)

Outcome: You've shipped a real, working agent without writing code.

This is where it gets tangible. You'll build a small but genuinely useful agent on a no-code platform.

Pick your platform (start with one):

  • n8n — the most capable for a serious hobbyist; visual workflow canvas with a dedicated AI Agent node. Free if self-hosted. Best if you want depth and to connect many apps. (n8n shipped a 2.0 release in early 2026 with native LangChain-based AI nodes.)
  • Zapier Agents — easiest if you already live in Zapier's 8,000+ app world; "Agents" is an add-on layer that adds autonomous AI steps. Best for quick, app-to-app automation.
  • Dify — best if your agent is chat/RAG-shaped (answer questions over your documents). Drag-and-drop, fast to a working chatbot.

Concepts you'll meet in practice: triggers, tools/actions, connecting apps (credentials), and where to insert a "human approves before it acts" step.

Build (choose the smallest useful version):

  • A "research assistant" that takes a topic, searches the web, and returns a tidy summary, or
  • An "inbox triage" agent that reads new items and drafts replies for your approval, or
  • A "document Q&A" agent (Dify) over a folder of your own notes.

You should be able to explain: the difference between an automation (fixed steps) and an agent (decides steps), from having built one.

Phase 3 — The Claude & Cowork ecosystem (1 week)

Outcome: You understand Anthropic's whole agent stack and can build custom agents inside the tools you already have.

Anthropic's stack has three layers that build on each other: MCP (how agents connect to tools/data) → Skills (reusable capability packages) → the Claude Agent SDK (the runtime developers use). As a non-coder, you'll mostly work at the top of this stack — Cowork, Projects, Skills, and MCP connectors — which is plenty powerful.

Learn, in order:

  • Claude Projects & Cowork — the no-code front door. How to give Claude a persistent role, files, and instructions; how Cowork uses your files, connectors, and skills to actually do things on your computer.
  • Skills — reusable SKILL.md capability packs that Claude auto-selects when relevant. You already benefit from these (docx, pptx, etc.). Learn how to ask for or commission a custom skill for a repeated task of yours.
  • MCP (Model Context Protocol) — the "USB-C for AI tools." It's the standard that lets an agent plug into apps (Gmail, Notion, Drive, Slack, etc.). Understand what a connector is and how permissions work.
  • Subagents & hooks (conceptual) — how a main agent delegates bounded jobs (research, review, QA) to specialist subagents with their own context. You don't need to code this, but knowing it exists shapes how you design bigger agents.

Do this course:

  • Anthropic Academy (anthropic.com/learn) — free, with a certificate. The MCP course (co-built with Hugging Face) and "Claude in action" material are the practical standouts.

Build: Set up a Claude Project (or Cowork workflow) for one recurring task of yours — with a clear role, the right files/connectors, and a repeatable instruction. Note where you'd want a custom Skill.

You should be able to explain: how MCP, Skills, and the Agent SDK fit together, and which layer you'd use for a given job.

Phase 4 — Design patterns & multi-agent thinking (½ week)

Outcome: You can design an agent on paper before building it, and know when to use more than one.

The seven patterns that are the shared vocabulary of agent design in 2026 — learn when each applies:

  1. Reflection — the agent critiques and improves its own output.
  2. Tool Use — it calls external tools to act or fetch facts.
  3. ReAct — it interleaves reasoning and acting step by step.
  4. Planning — it breaks a big goal into an ordered plan.
  5. Multi-Agent Collaboration — an orchestrator delegates to specialists.
  6. Evaluator-Optimizer — one agent produces, another scores and sends back for revision.
  7. Human-in-the-Loop — a person approves risky or ambiguous steps.

Also cover: single-agent vs. multi-agent trade-offs (multi-agent adds power and cost/complexity — use it only when a job has genuinely separable roles), and memory (short-term context vs. long-term vector/episodic memory).

Build: Re-read Anthropic's "Building Effective Agents" (it'll land now) and sketch — in words/boxes — the design of an agent for one of your projects using the patterns above.

You should be able to explain: when a second agent is worth it, and when it's just extra cost.

Phase 5 — Understanding the code frameworks (½ week, conceptual)

Outcome: You can tell which framework a developer or AI assistant should use, and speak the language — without writing the code.

You won't code these, but knowing them lets you commission builds intelligently. One paragraph each:

  • LangGraph — models an agent as a graph of steps with branches and loops; the most battle-tested for complex, stateful, production workflows. Reach for it (or ask a builder to) when the logic is intricate.
  • CrewAI — role-based "crews" of agents (researcher, writer, reviewer) collaborating on a task; the lowest barrier for team-of-agents prototypes.
  • Microsoft Agent Framework — strong for multi-agent conversations and code-heavy tasks; it's the 2026 merger of Semantic Kernel + AutoGen (Agent Framework 1.0 shipped April 2026; AutoGen itself is now in maintenance mode).
  • OpenAI Agents SDK — lightweight, good for handoff patterns where one agent passes to another; natural if you're in the OpenAI world.
  • Claude Agent SDK — Anthropic-native runtime with first-class subagents, Skills, hooks, and the deepest MCP integration; the one behind Cowork.

Do this (optional, skim): Hugging Face Agents Course Units 2–4, which build simple agents across a couple of these frameworks. Watch to understand the shape, not to memorize syntax.

You should be able to explain: "use LangGraph when…, CrewAI when…, Claude Agent SDK when…" in a sentence each.

Phase 6 — Reliability, evals, safety & cost (½ week)

Outcome: You know how to tell if an agent actually works and how to keep it safe and affordable.

  • Evals — how you know an agent is working: test it on real examples of your own tasks and score the results, rather than trusting one lucky demo. Learn the beginner habit of keeping a small "test set" of real inputs.
  • Guardrails & permissions — limiting what tools an agent can touch; requiring human approval for anything that sends, deletes, spends, or posts.
  • Cost — what drives spend (tokens, number of tool calls, multi-agent fan-out) and simple ways to keep it low (smaller models for simple steps, fewer agents, caching).
  • Privacy — what to consider before an agent touches your email, files, or accounts.

Build: Write a 5–10 item "test set" for the agent you built in Phase 2 or 3, run it, and note where it failed. Add one guardrail (e.g. a human-approval step).

You should be able to explain: how you'd prove to yourself that an agent is reliable enough to trust.

Phase 7 — Capstone: apply agents to your projects (1 week)

Outcome: At least one custom agent running for a real project of yours, plus a plan for the rest.

Use the Project → Agent worksheet below for each project on your list. Then pick the highest-value, lowest-effort one and build it for real, reusing what you learned in Phases 2–3.

Project → Agent worksheet (copy this per project)

  1. The job: In one sentence, what should this agent accomplish?
  2. Trigger: What starts it? (a schedule, a new email, you asking, a file appearing)
  3. Steps & tools: What does it need to do, and what tools/apps does each step need?
  4. Inputs & memory: What information does it need up front, and what should it remember between runs?
  5. Human-in-the-loop: Which steps must you approve before they happen?
  6. Build lane: No-code (n8n / Zapier / Dify), Claude (Project / Cowork / Skill / MCP), or commission a coded build? Why?
  7. Weekend v1: The smallest version you could get working in a weekend.
  8. Grown-up version: What it becomes if it proves useful.
  9. How you'll test it: 5 real examples and what "good" looks like.

One-paragraph spec (hand this to a builder or to Claude)

"Build an agent that [job]. It triggers when [trigger]. It should [step 1], [step 2], [step 3], using [tools]. Before [risky step], it must ask me to approve. It remembers [memory]. Build the first version in [lane]. I'll test it on [examples] and consider it working if [criteria]."

You should be able to explain: for each of your projects, the simplest agent that would help and how you'd build it.

Glossary (quick reference)

  • Agent — an AI system that pursues a goal by deciding its own steps and using tools, looping until done.
  • Tool use / function calling — the model's ability to call external actions (search, send email, run code).
  • ReAct — a pattern of interleaving reasoning ("think") and acting ("do") step by step.
  • RAG — Retrieval-Augmented Generation; the agent looks up relevant documents and uses them to answer.
  • MCP — Model Context Protocol; the open standard that lets agents plug into tools and data ("USB-C for AI").
  • Skill — a reusable capability package (a SKILL.md + assets) an agent auto-uses when relevant.
  • Subagent — a specialist agent a main agent delegates a bounded task to, with its own context.
  • Orchestration — coordinating multiple steps or agents toward one goal.
  • Memory — short-term (the current context window) or long-term (stored, retrievable facts/history).
  • Evals — tests that measure whether an agent produces good results, run on real examples.
  • Guardrails — rules/permissions that limit what an agent can do and require human approval for risky actions.
  • Human-in-the-loop — a person reviews or approves certain agent steps.
  • Context window — how much text (instructions, history, data) the model can consider at once.
  • Token — the unit of text models process and are billed on; more tokens = more cost.
