The Agents Research Prompt

A reusable, copy-paste prompt for deeply researching AI agents and custom agents. Paste it into any research-capable AI (Claude, ChatGPT, Perplexity, Gemini) that can search the web. Fill in the bracketed [...] variables first, or leave them and the AI will ask.

How to use this

  1. Copy everything inside the PROMPT block below.
  2. Replace the [VARIABLES] at the top with your own details (or delete a line to accept the default).
  3. Paste it into your AI tool and send.
  4. Use the follow-up prompts at the bottom to go deeper on any section.

Tip: run it once with defaults to get the lay of the land, then re-run focused versions (e.g. only "no-code platforms" or only "Claude Agent SDK") for depth.

PROMPT

You are my senior AI-agents research analyst and teacher. Your job is to research the
current state of AI agents and custom agents thoroughly, then hand me a decision-ready,
well-cited briefing that a smart non-coder can act on.

# MY CONTEXT (edit these)
- My skill level: [non-coder who builds with no-code tools and AI assistants; can follow guided steps but does not write production code]
- What I want to build: [describe your ongoing projects and any new ideas — e.g. "an assistant that organizes my files," "a research agent for my podcast," "a customer-support bot"]
- Tools I already use or have access to: [e.g. Claude / Cowork, ChatGPT, Zapier, n8n, Notion, Google Workspace]
- My goal: [understand agents well enough to design and commission/build custom agents for my projects]
- Budget sensitivity: [free-first, willing to pay for a couple of key tools]
- Depth: [comprehensive — I want the full landscape, not a quick summary]

# WHAT COUNTS AS "DONE"
Deliver a briefing that lets me (a) explain how agents work in plain language, (b) choose
the right approach for each of my projects, and (c) know exactly what to learn or build next.

# RULES
- Search the web and cite every non-obvious claim with a source link and its date.
- Prioritize primary sources (official docs, framework repos, vendor pages) over blog roundups.
- Flag anything that changed in the last 6 months, and note when something is likely to
  keep changing fast.
- When tools compete, give me a plain-English "use this when…" verdict, not a spec dump.
- Define jargon the first time you use it. Assume I'm smart but new to the terminology.
- Where you're uncertain or sources disagree, say so instead of guessing.
- No code unless I ask. When you must reference code, explain what it does in words.

# RESEARCH SCOPE — cover all of these

## 1. Foundations (plain-language)
- What an "AI agent" actually is, and how it differs from a chatbot, a workflow/automation,
  and a single LLM prompt. Give a crisp definition and a spectrum (assistant → workflow →
  autonomous agent).
- The core loop: perceive → reason/plan → act (tool use) → observe → repeat. Explain with a
  concrete everyday example.
- The building blocks every agent has: model, instructions/system prompt, tools, memory,
  and a control loop. Define each.
- Key terms I'll keep hearing, each in one sentence: tool use / function calling, ReAct,
  RAG (retrieval-augmented generation), context window, MCP (Model Context Protocol),
  orchestration, guardrails, evals, human-in-the-loop.

## 2. How agents are designed (patterns)
- The canonical agentic design patterns and when each is used: Reflection, Tool Use, ReAct,
  Planning, Multi-Agent Collaboration, Evaluator-Optimizer, and Human-in-the-Loop.
- Single-agent vs. multi-agent (orchestrator + subagents): trade-offs, and when multi-agent
  is worth the added complexity and cost.
- Memory: short-term (context) vs. long-term (vector/episodic memory). Why it matters and
  how it's usually implemented at a high level.
- Agentic RAG: what it is and when an agent should retrieve documents as a tool.
- The most common failure modes (loops, hallucinated tool calls, runaway cost) and how
  people mitigate them.

## 3. Ways to BUILD a custom agent — full landscape, four lanes
For each lane: what it is, who it's for, learning curve, cost, strengths, limits, and a
"pick this if…" line. Then a comparison table across all lanes.
  a. No-code / low-code platforms — e.g. n8n, Zapier Agents, Make, Dify, Lindy, Botpress,
     Flowise, plus custom GPTs / Claude Projects. Best current option(s) for a non-coder.
  b. Anthropic / Claude ecosystem — Claude Agent SDK (subagents, Skills, hooks, sessions),
     MCP, Claude Projects, and Cowork. What each is for and how they fit together.
  c. Code frameworks (conceptual, so I understand what developers/AI assistants use) —
     LangGraph, CrewAI, AutoGen / Microsoft Agent Framework, OpenAI Agents SDK. One
     paragraph each: what it's known for and its ideal use case.
  d. Managed / hosted agent products and API-native building. When to just use a hosted
     product vs. build your own.

## 4. MCP and tools (the connectivity layer)
- What MCP is, in plain terms, and why it's become the standard way agents connect to tools
  and data.
- How an agent gets "hands" — the kinds of tools agents use (search, files, apps, code,
  browsers) and how tool permissions/guardrails work.

## 5. Reliability, safety, and cost
- Evals: how do you know an agent is actually working? Beginner-friendly ways to test.
- Guardrails and permissions; keeping a human in the loop for risky actions.
- Cost drivers (tokens, tool calls, multi-agent fan-out) and how to keep spend sane.
- Privacy/data considerations when an agent touches my files, email, or accounts.

## 6. Best learning resources (ranked, mostly free)
- The single best free course to start with, and why.
- 5–8 more high-quality resources (official courses, docs, canonical essays, one or two
  YouTube/newsletter picks), each with a one-line "what you'll get."
- Note which are vendor-neutral vs. tied to one platform.

## 7. Apply it to MY projects
For each project I listed in MY CONTEXT:
- The simplest approach that would work, and the "grown-up" version if it takes off.
- Which build lane and specific tool(s) to use.
- The first concrete milestone I could reach in a weekend.

# OUTPUT FORMAT
1. Executive summary (about 10 bullet-equivalent sentences in prose): the 8–10 things I
   most need to understand right now.
2. A glossary of the key terms (term → one-sentence definition).
3. The full briefing, following the scope sections above, using clear headers.
4. A single comparison table of the build lanes/tools.
5. A "start here" section: my recommended first course, first tool, and first project.
6. Open questions / things to watch (what's still changing fast).
7. Sources: numbered list of every link used, each with its publication date.

Before you begin, if any of MY CONTEXT is blank or unclear, ask me up to 3 quick
questions. Otherwise, proceed.

Follow-up prompts (paste after the main briefing)

Use these to drill into any lane once you have the overview:

  • Go deep on no-code: "Focus only on no-code/low-code agent platforms for a non-coder. Compare n8n, Zapier Agents, Make, Dify, and Lindy on: ease for a beginner, cost, what kinds of agents each is best at, and how each handles connecting to my apps. End with a single recommendation for my projects and a first-build walkthrough in plain steps."
  • Go deep on the Claude/Anthropic stack: "Explain the Claude ecosystem for building custom agents as one coherent stack: Claude Projects, Cowork, Skills, MCP connectors, subagents, and the Claude Agent SDK. For each, tell me what it is, when I'd reach for it as a non-coder, and how they build on each other. Include the official docs links."
  • Understand the code frameworks without coding: "I won't write the code myself, but I want to understand LangGraph, CrewAI, AutoGen, and the OpenAI Agents SDK well enough to know which one to ask an AI assistant or developer to use. Give me a plain-English profile of each, a 'best for' verdict, and one real example of what each is commonly used to build."
  • Design a specific agent: "Help me design an agent for [PROJECT]. Walk through: the job it does, the trigger, the steps/tools it needs, where a human should approve, the memory it needs, how I'd test it, and the cheapest way to build a first version. Then give me a one-paragraph 'spec' I could hand to a builder or an AI."
  • Stay current: "What has changed in the AI agents world in the last 60 days? New framework releases, notable model/agent capabilities, and shifts in best practice. Cite dates and sources, and tell me what (if anything) changes my recommended approach."

Why this prompt is built the way it is

  • It assigns a role and a done-condition so the AI optimizes for a usable briefing, not a wall of text.
  • It forces citations and dates because the agent field changes monthly — undated claims age badly.
  • It separates "understand" from "build" so you get concepts and an action path.
  • It's parameterized — the MY CONTEXT block is the only thing you edit to re-aim it.
  • It ends by tying research back to your projects, which is where most research prompts stop short.
