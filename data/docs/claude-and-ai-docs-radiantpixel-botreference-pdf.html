Part 0 — What Is Radiant Pixel?
Radiant Pixel is a fully automated crypto trading bot. It monitors the X (Twitter) account @astronomer_zero for
buy and sell signals, uses Claude Haiku AI to parse those posts into structured trade instructions, checks them
against 9 risk management gates, and executes 10x leveraged perpetual futures trades on Phemex
automatically. All trade events are reported via Telegram.


Signal flow:

   #      Component                    What it does

   1      Twitter Monitor tweepy       Polls @astronomer_zero every 60 seconds for new tweets. Skips tweets older
          X API v2                     than 15 minutes.

   2      Signal Parser Claude         Sends each tweet to Claude Haiku. Returns structured JSON: signal type,
          Haiku AI                     entry price, stop loss, take profits, confidence score.

   3      Risk Manager 9-gate filter   Validates confidence, price levels, staleness, daily limit, open positions,
                                       conflicts, size, minimum order, and liquidation buffer.

   4      Phemex Executor CCXT         Sets 10x leverage, places market entry order, stop-loss order, and up to 3
          library                      take-profit orders split by configured ratios.

   5      SQLite DB database.py        Logs every tweet, trade open/close, and bot state. Deduplicates tweet IDs so
                                       nothing is processed twice.

   6      Telegram Notifier            Sends HTML-formatted alerts for every trade lifecycle event and daily P&L
          notifier.py                  summaries.

Part 2 — Signal Types (What Claude Haiku Detects)
Every @astronomer_zero tweet is sent to Claude Haiku. Claude classifies it into one of 6 signal types and
returns structured JSON. The bot acts on the type to decide what to do.

   Signal Type            What it means                                Bot Action

   entry_long             Buy signal — go long on BTC/ETH at           Opens long position (subject to 9 risk gates)
                          given entry price

   entry_short            Sell signal — go short on BTC/ETH            Opens short position (subject to 9 risk gates)
                          at given entry price

   close                  Close existing position now                  Cancels SL/TPs, market closes the position

   adjust_sl              Move stop loss to a new price level          Cancels old SL order, places new one at new price

   partial_tp             Partial take-profit hit or TP level          Logged only — Phemex TP orders handle
                          adjustment                                   automatically

   analysis_only          Market commentary, no actionable             Silently ignored — no trade, no alert
                          trade levels



Claude Haiku output schema (JSON returned for each tweet):
  { "signal_type": "entry_long | entry_short | close | adjust_sl | partial_tp |
  analysis_only", "symbol": "BTC | ETH", "entry_price": 104000, "stop_loss": 99500,
  "take_profits": [108000, 112000, 116000], "confidence": 0.85, "notes": "Optional reasoning
  string" }

  Rules baked into the system prompt: Non-whitelisted symbols (not BTC or ETH) are demoted to analysis_only.
  Confidence below 0.70 triggers a Telegram alert for human review — no trade placed. Tweets older than 15 minutes are
  skipped before parsing even starts.



Part 3 — Risk Manager: 9 Safety Gates
Every entry signal passes through all 9 gates in order. ALL must pass for a trade to be placed. Any rejection
sends a Telegram alert (except POSITION_EXISTS, which is silent).

        #     Code                              What it checks                                 Default

        1     LOW_CONFIDENCE                    Claude's confidence score for the signal       Min 70%

        2     MISSING_LEVELS                    Signal must have both entry_price and          Required
                                                stop_loss

        3     PRICE_STALE                       Phemex mark price vs. signal's stated          Within 2%
                                                entry price

        4     DAILY_LIMIT                       Day's net P&L vs. daily loss limit             Max −5%/day

        5     MAX_POSITIONS                     Count of currently open positions              Max 1

        6     CONFLICTING_POSITION              Same symbol open in opposite direction         Alert, skip

        6b    POSITION_EXISTS                   Same symbol already open in same               Silent skip
                                                direction

        7     INVALID_SL                        Stop loss equals entry (zero stop distance)    Rejected

        8     SIZE_TOO_SMALL                    Calculated position size vs. Phemex            Min 0.001
                                                minimum                                        BTC

        9     LIQUIDATION_TOO_CLOSE             Liquidation price distance from entry at 10x   Min 8% buffer



Position sizing formula (Kelly-inspired, 1% risk per trade):
  risk_dollars = account_equity × 0.01 # 1% of account stop_distance_pct = abs(entry −
  stop_loss) / entry position_size_usdt = risk_dollars / stop_distance_pct position_size_btc =
  position_size_usdt / entry_price margin_required = position_size_usdt / leverage # at 10x


Liquidation price formula (Phemex isolated margin, 0.5% maintenance margin):
  Long: liq = entry × (1 − 1/leverage + 0.005) → at 10x: ~9.5% below entry Short: liq = entry
  × (1 + 1/leverage − 0.005) → at 10x: ~9.5% above entry Gate 9 requires liq to be at least 8%
  away — all valid 10x trades pass this.
Part 4 — Order Execution on Phemex
Uses the CCXT library (ccxt==4.4.53) to communicate with Phemex's REST API.

4.1 Order flow for a new entry:

   St       Order type               Details
   ep

   1        Set leverage             exchange.set_leverage(10, symbol) — called once per symbol

   2        Market entry             Buy (long) or Sell (short) market order for position_size BTC

   3        Stop-loss                stop_market, reduce_only=True — placed at signal's stop_loss price

   4        Take-profit #1           take_profit_market, reduce_only=True — 40% of position at TP1

   5        Take-profit #2           take_profit_market, reduce_only=True — 35% of position at TP2

   6        Take-profit #3           take_profit_market, reduce_only=True — 25% of position at TP3



4.2 Supported contracts (set contract: in config.yaml):

   config value              Contract type             Margin currency         Phemex symbol

   BTCUSDT                   Linear perpetual          USDT                    BTC/USDT:USDT

   BTCUSD                    Inverse perpetual         BTC                     BTC/USD:BTC

   ETHUSDT                   Linear perpetual          USDT                    ETH/USDT:USDT



4.3 Close position flow:
       • Cancel all open SL and TP orders for the position
       • Place a reduce_only market order for the full remaining size
       • Estimate P&L; from entry price vs. exit mark price and log to SQLite

4.4 Testnet vs. live mode:
  Currently: TESTNET. All orders go to testnet-api.phemex.com (paper money). To go live: set
  PHEMEX_TESTNET=false in /opt/radiant-pixel/.env, then run docker compose up -d on the VPS.

Part 8 — SQLite Database (data/radiant_pixel.db)
Three tables persist all bot state across restarts.

8.1 processed_tweets — tweet deduplication

   Column               Type            Description

   tweet_id             TEXT PK         X tweet ID — prevents reprocessing the same tweet

   text                 TEXT            Full tweet text (stored for audit trail)

   signal_type          TEXT            What Claude classified this tweet as

   confidence           REAL            Claude's confidence score (0.0 to 1.0)

   processed_at         TEXT            ISO timestamp when the tweet was parsed



8.2 trades — full trade log

   Column                  Type            Description

   id                      INT PK          Auto-increment trade ID

   tweet_id                TEXT            Source tweet that triggered this trade

   symbol                  TEXT            Trading pair (e.g. BTCUSDT)

   direction               TEXT            long or short

   entry_price             REAL            Signal's entry price

   stop_loss               REAL            Stop loss price at open

   take_profits            TEXT            JSON array of take-profit prices

   position_size           REAL            Size in BTC (contracts)

   leverage                INT             Leverage used (10)

   liq_price               REAL            Calculated liquidation price

   phemex_order_id         TEXT            Entry order ID returned by Phemex API

   sl_order_id             TEXT            Stop-loss order ID (updated on adjust_sl signals)
   tp_order_ids          TEXT            JSON array of take-profit order IDs

   opened_at             TEXT            ISO timestamp of trade open

   closed_at             TEXT            ISO timestamp of trade close (NULL if still open)

   close_reason          TEXT            sl_hit, tp_hit, manual, etc.

   pnl_usdt              REAL            Estimated P&L in USDT at close



8.3 bot_state — key/value store

   Key                     What it stores

   last_tweet_id           Most recent processed tweet ID — used as since_id on next poll to avoid re-fetching

   paused_date             Date trading was paused (YYYY-MM-DD) for the daily loss limit check

   trading_paused          1 if trading is currently paused; 0 or absent if active

Part 11 — Switching from Testnet to Live Trading
Currently running in Phemex testnet mode. Follow this checklist before going live.

    [ ] Run on testnet for at least 1–2 weeks — verify all signal types work correctly in logs
    [ ] Confirm all Telegram alert types fire (trade open, close, SL update, daily summary)
    [ ] Verify position sizes are reasonable for your account balance (min 0.001 BTC ≈ $100 notional)
    [ ] Deposit USDT into your Phemex account (suggest $200–$500 to start)
    [ ] SSH to VPS: edit /opt/radiant-pixel/.env — change PHEMEX_TESTNET=true to
    PHEMEX_TESTNET=false
    [ ] Recreate the container: cd /opt/radiant-pixel && docker compose up -d
    [ ] Watch the first live trade Telegram alert and confirm the position appears on Phemex UI
    [ ] The bot will NOT auto-close positions on shutdown — always check Phemex before restarting
Daily loss limit: If the bot loses 5% of your account in one day, all new entries pause until midnight UTC. You get a
Telegram alert. Trading resumes automatically next day.
Conflicting signals: If @astronomer_zero posts a short while you're long, the bot will NOT auto-reverse at 10x
leverage. You get a Telegram alert and must decide manually on Phemex.

Troubleshooting quick guide:
   • No Telegram for hours → bot crashed. Check: docker compose ps
   • 401 Unauthorized (X API) → Bearer Token expired. Regenerate at developer.x.com and update .env
• Orders not on Phemex → Check API key has Trade permission and is bound to VPS IP 72.61.209.224
• SIGNAL SKIPPED / PRICE_STALE → BTC moved more than 2% from signal's stated entry before bot
could act
• Daily pause → Bot lost 5%+ today. Resumes automatically at midnight UTC. Check Phemex for open
positions
• CONFLICTING SIGNAL alert → You're long and a short signal arrived. Go to Phemex and decide
manually
• Position stuck open after bot restart → Close it manually on Phemex UI — bot never auto-closes on
shutdown
