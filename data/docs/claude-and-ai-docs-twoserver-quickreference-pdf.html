Part 1 — Architecture & Latency Philosophy
Every decision is made in service of latency. The bot's edge is speed — detecting a Binance price move
before the Polymarket CLOB reflects it. Any change that adds latency on the hot path (signal → decision →
order) must be justified by a larger gain. When in doubt, don't add it.

The architecture splits work by geography: Tokyo sits ~60 ms from Binance (AWS ap-northeast-1); London sits
~10 ms from Polymarket (AWS eu-west-2). This cuts the signal-to-order round-trip from ~220 ms (Jakarta
single-server) to ~145 ms.

Part 5 — Deploy Workflow
All bot code is version-controlled on GitHub. London clones from the repo via deploy key. Tokyo's relay script is
deployed via direct scp (not in the Docker image).

5.1 Standard bot deploy (London)

# Step 1 — commit and push on Mac

   cd /Users/rubys/Desktop/AI_bots/Polymarket-Arbitrage-Bot git add -p git commit -m "describe
   change" git push origin main

# Step 2 — pull, rebuild, restart on London

   ssh poly-london cd /opt/polymarket-bot git pull docker compose build polymarket-bot docker
   compose up -d polymarket-bot

   NEVER use --force-recreate — it causes Binance WS to fail on startup (Docker network namespace teardown breaks the
   initial TCP handshake). docker compose up -d without it picks up the new image automatically.

5.2 Deploy relay script update (Tokyo)

# Run on Mac — scp then restart

   scp -i ~/.ssh/hostinger_vps \
   /Users/rubys/Desktop/AI_bots/Polymarket-Arbitrage-Bot/signal_relay.py \
   root@45.63.122.65:/opt/signal_relay.py ssh poly-tokyo 'systemctl restart signal-relay'


5.3 Update .env on London

Part 7 — Managing the Signal Relay on Tokyo
Tokyo runs a WebSocket SERVER on port 9999. London connects to it as a client. The relay subscribes to
Binance aggTrade (per-trade, ~8/sec) and broadcasts each tick to all connected clients.

7.1 Service control

  Action                              Command (run on Tokyo)

  Restart relay                       systemctl restart signal-relay

  Start relay                         systemctl start signal-relay

  Stop relay                          systemctl stop signal-relay

  Check status                        systemctl status signal-relay

  Live logs                           journalctl -u signal-relay -f

  Last 10 lines                       journalctl -u signal-relay -n 10 --no-pager


Normal relay log output (once per minute):
  2026-05-05 22:51:32 [INFO] WebSocket relay server listening on port 9999 2026-05-05 22:51:32
  [INFO] Binance WS connected → serving on port 9999 2026-05-05 22:52:32 [INFO] Relay alive —
  481 ticks/min broadcast to 1 client(s)

  1 client = London is connected. 0 clients = London disconnected (check London bot). TKY:0s in London STATUS log =
  relay packets arriving. TKY:off = not yet connected.



Part 8 — Required .env Variables (London only)
Tokyo has no .env — it connects to Binance anonymously and serves WebSocket on port 9999.

        Variable                            Description                                        Required?

        PRIVATE_KEY                         Polygon wallet private key — 0x + 64 hex chars     Yes

        POLY_PROXY_WALLET                   Derived proxy wallet — 0x06b4...e204               Yes

        POLY_BUILDER_API_KEY                Polymarket CLOB API key                            Yes

        POLY_BUILDER_SECRET                 Polymarket CLOB API secret                         Yes

        POLY_BUILDER_PASSPHRASE             Polymarket CLOB API passphrase                     Yes

        TELEGRAM_BOT_TOKEN                  Telegram bot token from @BotFather                 Optional

        TELEGRAM_CHAT_ID                    Your Telegram chat ID                              Optional

        TOKYO_RELAY_URL                     Override Tokyo WS URL (default: ws://45.63.122.65:9999)
                                                                                            Optional

  PRIVATE_KEY pitfall: Must start with 0 (digit zero) + x, not O (capital letter O). A capital O causes a 'Non-hexadecimal
  digit found' crash at startup.
Part 9 — Cutover & Rollback
Jakarta (72.61.209.224) is kept as a warm standby. NEVER run London and Jakarta simultaneously — same
Polymarket wallet = double trades.

Switch to Jakarta (rollback):
  ssh poly-london "cd /opt/polymarket-bot && docker compose stop polymarket-bot" ssh
  poly-jakarta "cd /opt/polymarket-bot && docker compose up -d polymarket-bot"


Switch back to London:
  ssh poly-jakarta "cd /opt/polymarket-bot && docker compose stop polymarket-bot" ssh
  poly-london "cd /opt/polymarket-bot && docker compose up -d polymarket-bot"


Check which is running:
  ssh poly-london "cd /opt/polymarket-bot && docker compose ps" ssh poly-jakarta "cd
  /opt/polymarket-bot && docker compose ps"
