Onda Build Plan — What the Faceless-Channel Pipeline Needs

Grounded in Onda's actual code (studio/src/lib/config.ts, api/generate/route.ts, DOCS.md), not guesses. Onda today = 50 fal.ai models across two kinds only: image and video (plus 7 edit tools and Director), a credit ledger, Flow canvas, Library, Stripe. The faceless pipeline needs several things Onda doesn't have yet. Listed in build order.

What Onda already covers (no build needed)

Pipeline phaseOnda has it
Style-key image✅ 18 image models (FLUX, Seedream, Nano Banana, GPT Image 2, Recraft for vector/logo)
Per-block clips✅ 25 video models — t2v and image→video, duration scaling, end-keyframe on 7 families
Image editing (thumbnails base, restyle)✅ 7 edit tools incl. Nano Banana 2 Edit, GPT Image 2 Edit, erase, upscale

So the visual half of a faceless video is essentially done. The gaps are all in audio, assembly, and long-form orchestration — the parts that turn 60 clips into one publishable 10-minute film.

GAP 1 — Audio generation (TTS / voiceover) — HIGHEST PRIORITY

Why it's #1: A faceless explainer is narration-first. Without TTS, Onda cannot produce the single most important asset in the pipeline. Every other gap is downstream of having voice.

What's missing: ModelKind is "image" | "video" only. There is no audio lane in config.ts, no audio branch in buildInput, no audio dispatch in api/generate/route.ts.

What to build:

  • Add "audio" to ModelKind and an audio filter alongside IMAGE_MODELS/VIDEO_MODELS.
  • Add fal audio endpoints. fal hosts the same engines Magnific resells — e.g. fal-ai/elevenlabs/tts (ElevenLabs v3/turbo), plus MiniMax/PlayHT TTS. Price them with the existing ×3 rule (fal bills TTS per character/second — mirror the token-billed pattern already used for GPT Image 2).
  • Add a family (e.g. "tts") → buildInput shape: { text, voice_id, stability, similarity_boost, speed }.
  • Charge-first → run → auto-refund is already the pattern; audio reuses it.

Effort: Medium. It's a new kind, but it rides the existing generate/charge/refund/library rails.

GAP 2 — Voice cloning ("clone your own voice") — HIGH

Why: It's a named course module and a real differentiator — creators want their voice, not a stock one. Also a retention/upsell hook for Onda.

What's missing: No concept of a user-owned voice asset. Library stores creations (images/videos), not voice models.

What to build:

  • fal endpoint for voice cloning (ElevenLabs IVC via fal, or PlayHT). Input = a reference audio sample; output = a persistent voice_id.
  • A new Supabase table (user_voices: id, user_id, provider, external_voice_id, name) — the analog of Magnific's scope: mine voices.
  • Surface cloned voices in the TTS picker (Gap 1) as "My Voices".
  • Audio-file upload path: api/upload/route.ts today is images only, 10MB. Needs an audio branch (accept mp3/wav, larger cap).

Effort: Medium. Depends on Gap 1 existing first.

GAP 3 — Block assembly / concatenation ("the full 10-min video") — HIGH

Why: This is the piece that makes it a video, not 60 loose clips + 60 audio files. It's the hardest gap and the one with no clean fal equivalent — even Magnific leans on a bespoke assembler.

What's missing: No tool that syncs N (audio, video) block pairs into one timed MP4. No concatenation, no per-block trim/pad.

What to build (pick one path):

  • Path A — server-side ffmpeg job. A new backend route that takes an ordered list of {videoUrl, audioUrl} pairs, muxes audio onto each clip, trims/pads to block length, concatenates, optional burned captions. Runs on your VPS (you already deploy Docker on Hostinger) or a fal/serverless ffmpeg. Most control, most work.
  • Path B — fal assembly/stitch endpoint if one exists at build time (check fal's ffmpeg-api). Less control, faster.
  • Model it as a new kind: "assemble" job in the ledger so it's billed and refunded like everything else.

Effort: High. This is the real engineering lift. Recommend Path A for control.

GAP 4 — Dubbing / localization ("second language") — MEDIUM

Why: A named module and a strong multiplier (one video → many language markets), but it's post-production — the channel works without it.

What's missing: No dubbing lane. Magnific has a full dubbing studio (transcribe → translate → re-voice → caption, 12 languages).

What to build:

  • fal has dubbing endpoints (e.g. ElevenLabs dubbing). Add as an audio- or video-kind job: input a video URL + target language → dubbed video out.
  • Simpler MVP that reuses earlier gaps: re-run TTS (Gap 1) with a translated script + the cloned voice (Gap 2), then re-assemble (Gap 3). No new supplier needed — just a "translate script → regenerate audio track → remux" flow.

Effort: Low–Medium if built on Gaps 1–3; Medium if using a dedicated fal dubbing endpoint.

GAP 5 — Video cutting for Shorts ("20 shorts in one click") — MEDIUM

Why: Repurposing is high-leverage for reach, but it's downstream of having a finished long-form video (Gap 3).

What's missing: No cut/trim/crop/reframe tools. Onda's video models generate; none edit an existing video.

What to build:

  • A cut/crop route (ffmpeg again — shares infrastructure with Gap 3): input a long video + timestamp ranges → N vertical 9:16 clips.
  • Optionally a "find the best beats" helper (Claude reads the transcript, proposes short-worthy segments) — a natural Director-style extension.

Effort: Medium; largely reuses Gap 3's ffmpeg service.

GAP 6 — Thumbnails & titles — LOW (mostly covered)

Why low: Onda can already make the thumbnail image (image models + GPT Image 2 for on-image text + edit tools). The only missing pieces are YouTube-specific niceties.

What to build (optional polish):

  • A thumbnail template/aspect preset (1280×720) and a text-overlay helper — GPT Image 2 already renders text, so this is a prompt/preset, not a new supplier.
  • Title generation is pure LLM (Claude) — already available via the Director/Anthropic integration; just a new prompt.

Effort: Low. Mostly presets + prompts, no new infra.

Suggested build order (dependency-aware)

  1. Audio/TTS (Gap 1) — unlocks the whole narration half. Nothing works without it.
  2. Block assembly / ffmpeg service (Gap 3) — the other half; also the shared engine for Gaps 4 & 5.
  3. Voice cloning (Gap 2) — the differentiator; needs Gap 1.
  4. Dubbing (Gap 4) — cheap once 1–3 exist.
  5. Shorts cutting (Gap 5) — reuses Gap 3's ffmpeg.
  6. Thumbnail/title polish (Gap 6) — presets on top of what's already there.

The through-line: audio is the missing kind, and an ffmpeg service is the missing engine. Build those two and the faceless pipeline is ~90% Onda-native; everything else is presets and prompts on rails Onda already has (charge-first/refund, Library, Director, credit ledger).
