CLAUDE.md — building ShowKit

You are building ShowKit: an AI-generation storefront that resells wholesale image/video generation to content creators through a credit wallet. Read BUILD_PLAN.md for the full plan and docs/architecture.md for the system design. This file is the working rules.

What we're building (one sentence)

A Next.js web app where a user signs in, buys a subscription or credit pack via Stripe, and generates images/video through a metered credit ledger that calls third-party models server-side (OpenRouter / fal.ai / Replicate) and marks up the wholesale cost.

The spine (never break this flow)

request → authenticate → check balance → RESERVE credits → call provider (server-side) → on success SETTLE (deduct) + store output; on failure RELEASE the reservation → return

Every balance change writes an append-only row to credit_transactions. See lib/credits.ts.

Non-negotiables

  1. Keys server-side only. All provider + Stripe secret keys live in server env and never

reach the client. Every model call goes through app/api/generate/route.ts. (fal.ai's ToS forbids exposing its API to end users; Replicate permits use via your app — verify each.)

  1. Credit-ledger integrity. Balance mutations happen inside a single Postgres transaction.

Prefer reserve-then-settle so a failed/timed-out generation never charges the user. Idempotency keys on both /api/generate and the Stripe webhook. Credits are integers.

  1. Moderation is a launch blocker. Prompt + output moderation, plus a working NCII/abuse

report and 48-hour takedown flow (TAKE IT DOWN Act). Log prompts, outputs, and user IDs.

  1. The model catalog is data, not code. Models live in lib/models.ts

(id, provider, wholesale$, credits, capability). Adding a model = one data entry + a provider adapter — never a rewrite. Credit costs come from docs/unit-economics.md.

Conventions

  • TypeScript + Next.js App Router. Anything touching secrets, credits, or providers is a

server route handler / server action — never client code.

  • Store credits and prices as integers; keep the wholesale→credit mapping in one place

(lib/models.ts); round only at display.

  • Verify before "done" (house style): actually run the flow, hit the endpoint, and print

the resulting credit_transactions row. Don't hand back an untested generate or webhook.

  • No secrets in the repo. .env.local is git-ignored; .env.example documents the shape.

Build order

Follow BUILD_PLAN.md phases 0 → 5. Ship Phase 1 (auth + ledger + one working model generate, end-to-end) before adding breadth. A thin vertical slice that actually charges a credit correctly is worth more than ten half-wired models.
