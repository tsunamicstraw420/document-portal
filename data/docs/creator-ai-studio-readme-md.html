ShowKit (working name)

An AI-generation storefront for content creators. One credit wallet, the best image/video models under the hood, and one-click creator formats (thumbnails, Shorts, intros, audiograms, quote cards). You resell wholesale AI generation (via OpenRouter / fal.ai / Replicate) at a markup — the business model of davinci.ai / Pollo AI, but pointed at a niche you already own (podcasters + short-form creators, with your template + sound library and audience as the moat).

This folder is a handoff kit — not a finished app

It's meant to be opened in Claude Code to do the real build. Start with BUILD_PLAN.md.

Chosen stack

Next.js (App Router, TypeScript) · Supabase (Postgres + Auth + Storage) · Stripe (subscriptions + one-time credit packs) · model access via OpenRouter (unified image+text) and fal.ai / Replicate (fast image/video), all server-side. The credit ledger is the core of the product.

Get started (in Claude Code)

  1. Open this folder in Claude Code and read BUILD_PLAN.md.
  2. npx create-next-app on top of this scaffold (or wire these files into a fresh Next app).
  3. Copy .env.example → .env.local, create a Supabase project + Stripe (test) account +

an OpenRouter key, and fill the values.

  1. Build Phase 1 end-to-end first: sign in → trial credits → generate ONE model through

/api/generate with the ledger. That single slice proves the whole system.

Three constraints you cannot skip (details in BUILD_PLAN + CLAUDE.md)

  1. Provider keys are server-side only. fal.ai's ToS forbids exposing its API to end users

— every model call is proxied through your server. Never ship a provider key to the browser.

  1. Moderation + NCII takedown is a launch blocker. The TAKE IT DOWN Act requires a working

report + 48-hour removal flow (effective May 2026). Wire moderation before launch, not after.

  1. The credit ledger must be transactional and idempotent. Never double-deduct, never lose

a top-up. Stripe webhooks and generate requests both need idempotency keys.
