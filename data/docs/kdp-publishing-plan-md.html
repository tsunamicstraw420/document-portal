A "project" = one book in progress. Each gets projects/<slug>/config.yaml (inputs) plus generated artifacts (01_niches.md, manuscript.md, chapters/, titles_and_cover.md).

Pipeline design

Three CLI subcommands map 1:1 to the article's three prompts. Each stage reads config.yaml, renders the prompt template, calls the API, writes outputs. The user reviews between stages — no auto-chaining, since the article is explicit that you pick the niche manually after stage 1.

StageCommandInputs (from config.yaml)Output artifact
1. Niche researchkdp niche <project>category, audience, ad_budget01_niches.md
2. Manuscriptkdp write <project>title, audience, problem, length, tone, anglemanuscript.md + chapters/NN.md
3. Title & coverkdp optimize <project>topic, audience, benefit, competitors[]titles_and_cover.md

Stage 2 detail: the article notes "30,000–40,000 words across multiple sessions." Implementation: one call gets the outline + chapter list, then one call per chapter with the outline cached as a prompt prefix so each chapter call is cheap. Concatenate to manuscript.md at the end. Per-chapter files preserved so the user can edit selectively without regenerating the whole book.

--dry-run flag on every stage: render the filled prompt to stdout, skip the API call. Lets you sanity-check templates without burning tokens.

Prompt templates

Lift the three prompts verbatim from the article. Replace bracketed placeholders ([NON-FICTION / FICTION / specify], [TITLE], etc.) with {{snake_case}} tokens. The runner substitutes from config.yaml. No prompt rewriting — the article's wording is the spec.

Anthropic SDK details

  • Model: claude-opus-4-7 (latest, best for long-form writing).
  • Prompt caching enabled on the system prompt + outline for stage 2. The outline gets reused across N chapter calls, so caching turns N full re-reads into N cache hits.
  • Streaming on stage 2 chapter calls (long output, user wants progress feedback).
  • API key from .env via ANTHROPIC_API_KEY.
