The approach

A plain "render job", not Remotion's Google add-on

Remotion (the video maker we use) has its own Google Cloud add-on, but we can't use it here:

  • Its installer makes a service-account key file. Your Google organization blocks key files. That's the same block that made us connect solorender to Google without a key on Oct 20.
  • Remotion calls the add-on "in Alpha status and not actively being developed."
  • It stops any render after 60 minutes.

Instead, we package the same video maker that runs on your Mac and run it as a Cloud Run job. A job is a Google machine that switches on, does one task and switches off. Jobs can run up to 7 days, so there's no 60-minute cutoff. You start it from your Mac signed in as yourself, so it needs no key file.

Not known until the test
  • How long a render takes there. Google's 8 "processors" are probably slower than your Mac's 8 cores. My 40–80 minute guess is just that, a guess. The test gives the real number, and with it the real cost.
  • Whether 16 GB of memory is enough. If not, I raise it to 32 GB. That adds about a third to the machine cost.
  • Whether another organization rule blocks a step. If one does, I stop and tell you the exact message. I won't work around it.
Later, if you want speed

Run the same job on 6 machines at once, each doing a slice of the video, then join the slices. That gives the same total machine time, so about the same cost, and a 3½-minute explainer would take ~10–15 minutes instead of an hour. I'd do this only after the single-machine test works.
