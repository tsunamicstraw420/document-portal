onda-render-worker

The ffmpeg assembly worker for onda. Runs as a Render.com Background Worker (Docker). It polls the Supabase render_jobs queue, downloads each job's video blocks + narration, muxes and concatenates them into one MP4 (optionally with burned-in captions), uploads the result to the renders Storage bucket, and settles the credit ledger (charge first as assemble:<job id>, auto-refund on failure — both once-only per job, so crash retries can never double-charge).

The main onda app (Vercel) only enqueues jobs by inserting render_jobs rows; this worker only consumes them.

Job spec (the spec jsonb column)

{
  "credits": 30,
  "blocks": [
    { "videoUrl": "https://…/clip1.mp4", "audioUrl": "https://…/voice1.mp3" },
    { "videoUrl": "https://…/clip2.mp4" }
  ],
  "captions": [
    { "start": 0, "end": 3.2, "text": "First line" }
  ]
}
  • credits — what to charge the user (the app computes it at enqueue time).

0/absent = free render.

  • blocks — ordered; audioUrl is optional per block (silence is used so all

blocks concat cleanly). Every block is normalized to the first clip's resolution, 30 fps, H.264 + AAC.

  • captions — optional; either an array of {start, end, text} (seconds) or a

raw SRT string. Burned into the final video.

One-time Supabase setup

Run supabase/render.sql from the main onda repo (studio → supabase/render.sql) in the Supabase SQL Editor. It creates the render_jobs table + RLS, the claim_render_job() RPC (atomic claim via for update skip locked), the service-role spend_credits_for() ledger function, and the public renders Storage bucket. If the bucket insert is rejected, create it in the dashboard: Storage → New bucket → name renders → Public.

Deploy on Render

  1. Push this repo to GitHub.
  2. Render dashboard → New → Background Worker → connect the

onda-render-worker repo.

  1. Language: Docker (auto-detected from the Dockerfile). Branch: main.

Region: a US region (Oregon/Virginia/Ohio — ideally the one closest to your Supabase project).

  1. Instance: Starter to begin with; bump to Standard if 1080p renders feel slow.
  2. Environment variables:
  • SUPABASE_URL
  • SUPABASE_SERVICE_ROLE_KEY (the secret/service_role key — same one the

Stripe webhook uses)

No FAL_KEY — this worker never calls fal, it only assembles clips that already exist.

  1. Create the worker. Every push to main auto-deploys.

Local run

cp .env.example .env   # fill in the two values
npm install
node --env-file=.env worker.js

Requires ffmpeg on your PATH (brew install ffmpeg on macOS).
