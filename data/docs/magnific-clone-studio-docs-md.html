1. The money, in one rule

solorender credits = fal wholesale $ × 3 ÷ $0.01 — 1 credit = $0.01 sticker (500 = $5). ~67% gross margin on generation. Standing discount: image edit/upscale tools and video clip tools are priced at wholesale × 2 (~50% margin) instead of × 3 — each shows a "Discounted" badge in the picker with the pre-discount price struck through. Floors on the cheapest models push margin higher (the cheapest discounted tools floor at 2 credits); token-billed models (GPT Image 2 / 2.5) are priced against top quality; uploads are downscaled to 2048px to bound per-megapixel tools.

Video prices scale with user choices. Tables show the base clip; longer length multiplies credits linearly (rounded up); resolution applies a verified multiplier (Seedance 2.5 1080p ×2.46 · H3 480P ×0.63 · PixVerse v6 / Wan 3.0 / Omni Flash ladders) and only exists where fal's tier price is verified — everything else stays pinned. Audio, music and lip-sync also scale by the unit fal bills (see §5–§7). The Director (Claude writes the motion prompt from notes + reference images) is a Flow helper at 9 credits, priced near cost; Render film (stitch clips into one MP4) is 5 credits + 1 per clip, also priced near cost. House accounts (owner emails in OWNER_EMAILS) self-grant free credits from the dashboard — the owner pays only the wholesale bill; grants are ledger-logged as "owner grant".

10. How a new model gets added

  1. Verify it exists and is live — fal's catalog API: api.fal.ai/v1/models?endpoint_id=… returns metadata.status (active / deprecated), category and dates (no key needed; ~1 req/s or it 429s). Schema: fal.ai/api/openapi/queue/openapi.json?endpoint_id=…; null = bad id.
  2. Confirm the input shape — each family maps to a request format in buildInput. Check the DEFAULTS too: a flag you don't send (audio on, rendering speed, resolution) is what fal bills.
  3. Verify the price — the model page's publicEndpointBilling JSON gives the headline unit/price; the pricing paragraph gives the tiers (audio on/off, resolution). Price the tier the app actually REQUESTS, at LIST rates, never promos; pin or multiplier-price resolutions; scale durations/characters/seconds by the unit fal bills.
  4. Wire & ship — config entry, type-check, picker check, /help + this doc, commit. No paid test runs.

Lesson 2026-09-20: two models were quietly under-priced for weeks because the price was read off a cheaper tier than the request asked for (Seedance 2.5 at 480p while sending 720p; Ideogram Character at TURBO while fal defaulted to BALANCED), and two were over-priced off stale numbers. Nothing re-checks fal after a model is wired — hence the weekly model-scout task.

Two production bugs found while testing (2026-10-02) — both fixed and deployed.

  1. MCP upload published server memory. solorender_upload's base64 path used

Buffer.from(b64,"base64").buffer — small Buffers live in Node's shared pool and .buffer is the WHOLE pool, so a 325-byte PNG was stored at a public fal URL as 65,536 bytes of unrelated server memory (stray HTTP text, 2 email addresses; no keys in that sample). Fix: slice by byteOffset/byteLength. Never call .buffer on a Buffer. Earlier base64 uploads (since the MCP server launched 2026-09-21) may have leaked memory the same way.

  1. Stalled generations kept the customer's credits. Pictures/audio wait on fal.subscribe

synchronously; at maxDuration (300s) the platform kills the function and the refund in the catch never runs. HiDream I1 stalled: charged, no result, no refund. fal's own subscribe timeout is documented "currently not enforced", so the route now races its own 270s deadline, cancels the fal job, and falls into the refund path. Also seen: the MCP key is part of the URL (/api/mcp/<key>), so Vercel's request logs contain it in plain text — anyone with log access can read it. Worth moving to a header eventually.
