solorender — how it's wired (money & machinery)

Internal reference. Every generation solorender sells is bought wholesale from fal.ai and resold as credits. Tables below are GENERATED from the live pricing config (src/lib/config.ts) joined with verified fal costs — regenerate, don't hand-edit.

1. The money, in one rule

solorender credits = fal wholesale $ × 3 ÷ $0.01 — 1 credit = $0.01 sticker (500 = $5). ~67% gross margin on everything. Floors on the two cheapest models; token-billed models (GPT Image 2) priced against top quality; uploads downscaled to 2048px to bound per-MP tools.

Video prices scale with user choices. Tables show the base clip; longer length multiplies credits linearly (rounded up); resolution applies a verified multiplier (Seedance 2.5 1080p ×2.15 · H3 480P ×0.63 · PixVerse v6 ladder) and only exists where fal's tier price is verified — everything else stays pinned. The Director (Claude writes the motion prompt from notes + reference images) is a helper at 9 credits, priced near cost. House accounts (owner emails in OWNER_EMAILS) self-grant free credits from the dashboard — the owner pays only the wholesale bill; grants are ledger-logged as "owner grant".

7. How a new model gets added

  1. Verify it exists — fal's schema endpoint (fal.ai/api/openapi/queue/openapi.json?endpoint_id=…); null = bad id.
  2. Confirm the input shape — each family maps to a request format in buildInput.
  3. Verify the price — the model page embeds structured billing_unit/price JSON; price at LIST rates, never promos; pin or multiplier-price resolutions; scale durations.
  4. Wire & ship — config entry, type-check, picker check, commit. No paid test runs.

18 image + 7 edit + 25 video = 50 models live · Flow canvas · Director · Library · house accounts. The ×3 rule and the plumbing hold as the catalog grows. End-user guide: /help in the app (app/(app)/help).
