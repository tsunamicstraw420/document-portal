clip-recorder

Unattended screen recording of the solorender app. Nobody has to sit and film anything — a headless Chromium drives the real product and writes MP4s.

One episode produces two files, and they are not the same footage cropped:

FileSizeLayoutFor
<slug>--desktop-16x9.mp41920×1080desktoptutorials, YouTube, the docs
<slug>--social-9x16.mp41080×1920phoneShorts, TikTok, Reels, Facebook, Pinterest, LinkedIn, X

solorender is responsive, so each run renders the layout that shape was designed for. No letterboxing, no re-cut, no panning around a wide screenshot.

Setup (once)

cd studio/tools/clip-recorder
npm run setup

That installs Playwright and its Chromium (~100 MB, cached outside this repo). ffmpeg must be on PATH — it already is on Eddie's Mac (/usr/local/bin/ffmpeg).

Use

Start the app first (npm run dev in studio/), then:

node record.mjs --model img-flux2-pro --prompt "Make it Lego." --slug nano-lego
node record.mjs --episodes episodes.example.json
node record.mjs --episodes episodes.example.json --format social

Options: --base (default http://localhost:3000), --out (default ./out), --pace (ms per keystroke, default 45), --format (both | desktop | social).

The prompts in studio/src/lib/model-guides.ts are the script library — each starter prompt is one episode.

Two traps this script already handles

Both were found by getting them wrong, so don't "simplify" them away:

  1. The CSS viewport width picks the layout, not the output size and not

isMobile. A 1080-wide viewport is past the md: breakpoint (768px), so it renders the desktop layout stretched into a tall frame with a dead void below. The phone layout needs a genuinely narrow viewport (360px).

  1. Playwright's deviceScaleFactor does not feed the video encoder. It only

scales the viewport down into the output frame, never up — so a narrow viewport plus a large recordVideo.size comes out pillarboxed in grey. The thing that actually raises the raster is Chromium's --force-device-scale-factor launch flag. Both are set and must agree.

What it deliberately does NOT do

It never clicks Generate. A real run spends credits, and this has to be safe to re-run a hundred times. It types the prompt and lands on the price. Produce the generated asset separately (the solorender MCP tools) and composite it in.

Why it is isolated

Its own package.json, excluded from the app build via studio/.vercelignore. The root npm install never sees it (no workspaces) and tsc never reads it (.mjs is outside the tsconfig include), so it cannot slow or break a deploy.
