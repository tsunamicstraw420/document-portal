The standing rule going forward

Ruby ≤ 30% of runtime. She's the voice, not the visual. Before generating anything new, check the EP-01/EP-02 bank for a story-neutral clip that fits.

This is enforced in code. build_timeline.py refuses to write the timeline if Ruby exceeds 30%, and tells you how many seconds to cut. (Verified by forcing the cap to 25% — it aborted with "Cut ~23s: reuse a story-neutral clip from a previous episode.")

Order of preference when filling time:

  1. Reuse an existing story-neutral clip (free, instant)
  2. Second beat of a clip already made for this episode, with Ruby between so nothing repeats back-to-back
  3. Generate new — only when the moment is specific and nothing in the bank fits
  4. Ruby — last resort, because it costs lip-sync

Where reuse works best: hot-take beats, transitions between couples, the preview, the outro, and the Patreon/CTA read — anywhere she's commenting rather than describing a specific new event.
