Ruby Lip-Sync Bake-Off
Pick the tool that makes Ruby’s mouth look best — then we automate the rest.

Why we’re doing this
The first time we tried lip-sync we used a tool called Wav2Lip. It only repaints a tiny 96-pixel patch over
Ruby’s mouth, trained on real faces — so on her illustrated face it came out soft, blurry, and a little
wobbly. That’s why we paused it. Since then the free tools have gotten much better, and a few now fix
exactly that weakness. This is a quick taste-test: run the same Ruby clip through each one and see
which looks best on her.

Fastest way to decide (no install — ~15 min)
Use the free hosted demos. Upload the same two files to each one: ruby_test1.mp4 (the silent clip)
and ruby_test1.wav (Ruby’s narration), both in the bakeoff_test folder. Download each result and
compare.

   1. LatentSync — huggingface.co/spaces/fffiloni/LatentSync
   2. MuseTalk — huggingface.co/spaces/TMElyralab/MuseTalk
   3. OmniSync / Kling — app.klingai.com → AI Human / Lip Sync. Upload the clip + audio. (Uses Kling
   credits; a free trial usually covers one test.)
If a Hugging Face demo is busy or asleep, wait a minute and retry, or just use the Colab notebook below — it runs the
same two free models on your own free GPU.


The other way: the Colab notebook (also free)
Ruby_LipSync_Bakeoff.ipynb runs LatentSync and MuseTalk on Google’s free GPU and stitches the
results side-by-side into one comparison video. Open it at colab.research.google.com (File → Upload
notebook), then follow the numbered cells — it tells you exactly what to click. This is also the file we’ll
reuse to batch-process a whole episode once you pick a winner.


What to look for when judging
   • Sharpness — is the mouth crisp, or blurry like the old Wav2Lip?
   • Style match — does the mouth still look like Ruby’s graphic-novel art, or like a real photo pasted
   on?
   • Timing — do the lips actually match the words?
   • Steadiness — any jitter or flicker around the mouth between frames?
