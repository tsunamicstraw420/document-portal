Automated YouTube uploader — setup & use

Uploads the Season 3 audio-only episodes to YouTube unattended: video + title + description + tags + Entertainment category + made-for-kids = No + custom thumbnail + visibility, in one double-click.

Files:

  • youtube_upload.py — the uploader.
  • RUN_YOUTUBE_UPLOAD.command — double-click to run it.
  • _SHARED/client_secret.json — your Google OAuth client (you create this once, below).
  • _SHARED/yt_token.json — cached sign-in, created automatically on first run. Never share it.
  • _SHARED/uploaded_state.json — which episodes are already up, so re-runs don't double-post.

One-time setup (≈10 minutes, do it once)

Sign in to Google as the podcast account realityrecapsunfiltered@gmail.com for every step below (NOT the personal gmail).

  1. Google Cloud Console → https://console.cloud.google.com/ → create a

project (name it e.g. RRU-Uploader), or pick an existing one (the podcast's rru-pipeline project is fine).

  1. Enable the API: search the top bar for "YouTube Data API v3" → open it

→ Enable.

  1. Google Auth Platform setup wizard (Google's newer flow — this used to be

called the "OAuth consent screen"). It appears as a 4-step wizard the first time: App Information (App name e.g. RRU Uploader; User support email) → Audience = External → Contact Information (an email) → Finish (tick the agree box, Create).

  1. Add the test user: left nav → Audience → confirm Publishing status is

Testing → Test users → + Add users → add realityrecapsunfiltered@gmail.com → Save. (Required — without it, sign-in is blocked. Leave the app in Testing; no need to publish it.)

  1. Create the credential: left nav → Clients → Create client →

Application type Desktop app → Create → Download JSON.

  1. Put that downloaded file here, renamed exactly:

_SHARED/client_secret.json (full path: 90Day_LastResort_Season3/_SHARED/client_secret.json).

That's it. You never touch the console again for normal uploads.

Uploading

Double-click RUN_YOUTUBE_UPLOAD.command.

  • First run only: a browser opens. Sign in as realityrecapsunfiltered@gmail.com

and click Allow. Google will warn the app is "unverified" — click Advanced → Go to (app) (unsafe); it's your own app. The sign-in is then cached in _SHARED/yt_token.json, so later runs need no browser.

  • The tool prints the channel it signed in as first — confirm it says the

Reality Recaps channel before it uploads.

  • It uploads every ready episode that isn't already up, sets everything, and

prints a summary table (episode → videoId → visibility → thumbnail → URL).

Default visibility is Unlisted (see caveat below). To go straight to Public instead, run from Terminal:

./RUN_YOUTUBE_UPLOAD.command --visibility public

Adding future episodes (the reusable part)

Make a new folder _READY_TO_UPLOAD/EP##_S3E#/ containing exactly:

  • S3E#_AUDIO_ONLY.mp4
  • S3E#_thumbnail.png
  • S3E#_YOUTUBE_METADATA.md (same layout as the existing ones — the tool reads

the recommended A title, the ## DESCRIPTION block, and the ## TAGS block)

Then double-click RUN_YOUTUBE_UPLOAD.command again. New episodes upload; already-uploaded ones are skipped. Nothing else to configure.

Two things to know up front

  • Unverified-app lock → upload as Unlisted, flip to Public by hand. Until

Google formally verifies the app, videos the API uploads are forced toward Private/Unlisted and can't be flipped to Public through the API. So the tool uploads Unlisted (file, title, description, tags, thumbnail all done automatically); you flip each to Public in YouTube Studio with one click. (If you'd rather the API set Public directly, the app has to pass Google's OAuth verification — a separate, slower process.) Note: flipping a video Public publishes it on YouTube only. It does NOT post to Facebook or send email — those are still manual (no Zap #2 / MailerLite yet) — and it does NOT touch the podcast RSS feed, which comes from a separate upload to Spotify for Creators. See SPOTIFY_FOR_CREATORS_GUIDE.md.

  • Daily quota ≈ 6 uploads. Each upload costs ~1600 of the default 10,000

daily API units, so ~6 videos/day. With 7 episodes, the 7th may hit the quota and the tool stops cleanly — just double-click again the next day and it finishes the last one automatically (the state file remembers what's done). To deliberately cap a run: ./RUN_YOUTUBE_UPLOAD.command --limit 6.

Options (all optional)

./RUN_YOUTUBE_UPLOAD.command --dry-run            # show what WOULD upload, no API calls
./RUN_YOUTUBE_UPLOAD.command --visibility public  # or unlisted (default) / private
./RUN_YOUTUBE_UPLOAD.command --limit 6            # cap uploads this run

The click-to-copy S3_AUDIO_ONLY_UPLOAD_GUIDE.html remains as the fully-manual fallback if you ever want to paste everything into Studio by hand.
