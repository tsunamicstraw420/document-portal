🎯 Project Vision

Turn hours of manual podcast video editing into 30–60 minutes (or less) per episode through intelligent automation.

Core Problem We Solve:

  • Podcast hosts (especially recap shows) spend too much time hunting for B-roll, placing it contextually, removing fillers, adding captions, and repurposing long-form into Shorts/Reels.
  • Existing tools are either too generic, expensive, or don’t deeply understand spoken content to pick the right visuals at the right moment.

Our Goal: Build a customizable, local-first Python pipeline that:

  1. Analyzes your podcast transcript/audio
  2. Generates smart B-roll suggestions or fetches/generates matching visuals
  3. Composites everything into polished YouTube-ready videos + vertical clips
  4. Gives you full control (no black-box SaaS lock-in)

Why This Project Exists (Conversation Origin)

This project was born from an in-depth research session covering:

  • AI tools for podcast editing (Riverside.fm AI B-roll, Descript Underlord, Kapwing, Opus Clip, Pictory, BIGVU, CapCut, Runway/Pika for generative B-roll)
  • Specialized GitHub repos for transcript → B-roll → MoviePy/FFmpeg pipelines
  • The challenge of pulling 10–20 second clips from actual TV episodes discussed on the podcast (Playphrase.me, find-scene.com, Twelve Labs semantic search, FFmpeg extraction)
  • Heavy emphasis on copyright/fair use risks — actual episode clips are high-risk for monetized content
  • User’s existing setup: Riverside recording, Python experience (trading bots, .env, Mac dev), desire to scale reality TV recap podcast + YouTube channel efficiently
  • Desire for hybrid workflow: Start with no-code tools (Riverside/Descript/Kapwing) → move to custom Python pipeline for scale and control

Key Insight from Research: The best long-term path is a forkable Python pipeline (starting from strong existing repos) + LLM-driven intelligence for B-roll decisions, combined with safe stock/generative visuals and optional (high-caution) actual clip support.

⚠️ Critical Legal & Copyright Guidance

Using actual clips from TV episodes (reality shows, etc.) as B-roll carries significant risk:

  • Copyright holders actively use Content ID and manual claims on YouTube.
  • Even 10–20 second clips can trigger demonetization, blocks, or strikes.
  • Fair use is a defense, not a right. Commercial/monetized use + illustrative (non-transformative) B-roll weighs heavily against fair use.
  • Tools like Playphrase.me, find-scene.com, and Twelve Labs make finding clips easy — they do not grant usage rights.

Project Policy (Recommended):

  • Default / Recommended path: Use stock footage (Pexels/Pixabay) + generative AI B-roll. This is safe, scalable, and often looks more professional for recap content.
  • Actual episode clips: Only as an advanced, opt-in module. Always:
  • Keep clips very short (<10–15s)
  • Layer heavy original commentary, text overlays, zooms, reactions, or picture-in-picture of you
  • Never use clips that could substitute for watching the original show
  • Consult an IP lawyer for your specific use case and jurisdiction
  • Document fair use reasoning per clip

This project will include clear warnings and make the risky path opt-in only.

  2. Clone this project:

  1. Set up environment:

   pip install -r requirements.txt
