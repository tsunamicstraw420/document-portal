Credits — how we split the work (IMPORTANT)

Magnific's "Unlimited" only works inside the web app, on unlimited-tier models. The MCP/API always burns credits — every generation Claude runs through the connector deducts from the pool, even on models that are free in the app. Confirmed on Magnific's own pricing + API docs.

So the division of labor:

  • Eddie = the generator. All keyframe images and video clips are generated by Eddie in the Magnific web app on unlimited models → zero credits.
  • Unlimited image models: Nano Banana 2, Seedream 5.0 Lite, Flux.2 Pro (also Grok, Recraft).
  • Unlimited video models: Kling 2.5 720p and MiniMax Hailuo 2.3 Fast (most other video models burn credits).
  • Claude = the director/writer/organizer. Over MCP (free/cheap reads only): transcribe, beat sheets, shot lists, exact prompts, folder organization, character management, captions. Claude does NOT generate media through the connector.
  • Start each episode by creating a NEW episode-named Magnific space (spaces_create, e.g. LastResort_S3E12) and stage every keyframe/clip node inside it for Eddie; he runs them one-at-a-time in that space (unlimited, free). One space per episode keeps that episode's nodes and picks together. (Added Aug 21 2026.)

Measured cost (July 2026): a batch of 5 stills + 1 animated clip via MCP = 975 credits (the video is ~90%; stills ~40–60 each; a 5–10s clip ~700–800). So per-shot via MCP ≈ 750–850 credits. At that rate 45,000 credits ≈ ~55 shots ≈ ~7 min of finished animation — under half of ONE 15–20 min episode. Conclusion: episode keyframes + clips MUST be generated by Eddie in-app (unlimited, free); reserve credits for audio (always paid), occasional connector jobs, and days Eddie delegates.

Audio rule

Animated characters have no voices and no character sound. The only audio in an episode is Ruby's narration, plus music and SFX we deliberately add.

🚫 NEVER animate a cast character's mouth. Because they have no audio, moving lips read as talking with no sound — uncanny and wrong. Convey every beat with body language only: shrugs, head turns, jaw tightening, eyes narrowing or widening, brows jumping, shoulders dropping, leans, hand gestures, breathing, closed-lip expressions. DO animate hair, clothing, and background (foliage, trees, candles, curtains, drifting mist) — the frame should breathe; only mouths stay still (Eddie, Aug 21 2026). Ban "speaks / talking / says / laughs / mid-sentence / mid-tirade" from cast motion prompts, and append to every people-shot motion prompt:

Everyone's lips stay closed and completely still — nobody speaks, nobody talks, no mouth movement, no dialogue, no singing, no laughing out loud; expression and body language only.

(Skip that clause on location plates with no people.)

Ruby is the only character who ever ends up with a moving mouth — and NOT from the prompt. Her host loops are generated the same way as everyone else: closed mouth, no talking in the prompt. The mouth movement is added afterward, in post, by running that finished loop through Kling lip-sync via the Kling Developer API against Ruby's real recorded narration. So:

  • Generation stage (Magnific): nobody talks — cast or Ruby.
  • Post stage (Kling API): lip-sync applied to Ruby's booth/host loops only, never to cast shots.

Magnific staging & the @-name prompt formula — LOCKED Aug 21 2026

One episode space, in the 90Day project. Each episode = one Magnific space (e.g. S03E10). spaces_create lands it in Personal — move it into the 90Day_LastResort_Season3 project with projects_move (elementType space, the space UUID, target project ref). Magnific auto-renames the board by its content after you add nodes — rename it back to S03E## in-app at the end. Copy the reused assets in with spaces_add_creations: the castle establishing stills from the Architectural Fantasy Illustrations space + the couple-reference portraits. Everything for the episode lives in that one space (Eddie: no jumping between spaces).

The node graph (copy the S03E11 space, never invent): character references nodes → SC-## KF image-generator nodes (imagen-nano-banana-2-flash, 16:9, 1k) → Kling-3 video-generator clip nodes. Each keyframe is wired to its character-reference node(s); two-character scenes wire BOTH. Stage everything un-run (idle) — Eddie generates one at a time in-app (free/unlimited). NEVER run a node through the connector — that burns credits.

The prompt formula (proven Aug 21). Name each character with an @-tag (@shekhina, @sarper), add "take each character entirely from their reference," and describe NO clothing — the reference then supplies the exact outfit. (Nano Banana invents clothing if you describe it, and describing clothes fights the reference; the character ref locks the face, the @-tag + "from reference" locks the outfit.) No wardrobe lists. No reserved negative space for bubbles (renders as an ugly void). Always append "no text, letters, captions, speech bubbles, or watermark." Style block stays: vibrant jewel-tone graphic-novel. Animate hair/clothes/background, never mouths (puppets may move).

Board-editor quirk (verified 3×): the spaces_edit AI editor writes @-prompts on create but silently no-ops when asked to update an @-prompt (reports "success," changes nothing). Plain prompts edit in place fine. So: any change to an @-prompt = delete the node and recreate it. ALWAYS verify a prompt change with spaces_state / spaces_get_nodes — never trust the 'success' status.
