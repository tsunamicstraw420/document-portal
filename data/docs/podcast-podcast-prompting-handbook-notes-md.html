Prompting Handbook — working notes

Source: The Prompting Handbook v1.2, Magnific Studios, July 2026 (prompt-guide-v1-2.pdf). Digested Aug 5 2026. The full playbook is saved as the visual-prompting skill and loads automatically in any session — this file is the podcast-specific reading of it.

The core idea

Describe a coherent scene in plain language. Not a pile of keywords. The model builds what you describe and fills every gap you leave open with its most average answer.

What changes for Reality Recaps Unfiltered

1. "Slop" has a name now — and it's exactly our failure mode

Every model drifts to the same default: subject centred, staring at the lens, posed, evenly lit, everything in focus, plastic gloss. Audiences clock it in half a second. Our fix is two habits — direct the shot (off-centre framing, a caught moment, foreground depth) and finish the grade (gentle contrast, creamy focus roll-off, fine uniform grain).

Banned words. Never write these: ultra sharp · hyper detailed · crisp · razor sharp · 8K clarity · HDR · ultra-realistic detail.

Skin-realism block — paste whenever skin is visible (i.e. every Ruby plate and every cast shot):

Natural skin texture: realistic pores, fine hairs, subtle veining, a faint highlight. Tactile and real, not retouched plastic.

2. Character sheets = what we already do with Ruby, formalised

The handbook's rule matches our multi-angle character refs exactly: build a three-panel sheet (straight-on, side profile, full body) before a character appears twice, and every later generation carries it as a reference.

Its extra rule we should adopt: when the character changes, the sheet changes first. New wardrobe, new set, new hair → regenerate the sheet, then prompt from the new sheet. A character has exactly one current sheet at any time. That's the discipline that stops Ruby drifting between episodes.

3. "Rewrite the first frame" — a pipeline we should be using

The strongest video edits aren't made in a video model:

  1. Take the clip.
  2. Extract frame one as a still.
  3. Edit that still in Nano Banana Pro (image-grade instruction-following — name the change, pin everything else).
  4. Re-render with the edited frame as start frame + the original clip attached as a motion reference: "Repeat the exact same move as @video1, now around the new subject. Same pacing, same framing, one continuous take. No cuts."

Start frame pins what it opens on; the video reference pins how it moves. This is how we change one detail in an approved shot without regenerating and losing likeness.

4. Location coverage from a single still

Drop one set still in as a start frame and prompt a slow fly-through that rotates and stops for a beat facing each angle. Every held beat is an extractable frame with matching light and set. That's a whole episode's worth of Ruby-set angles from one approved plate, all consistent — which generating each angle separately can never guarantee.

Name each rotation and give it a stop. Never ask for "multiple angles."

5. Rules that map straight onto our shot lists

  • One action, one camera move per clip. Stacking either produces warping. (Confirms our existing rule.)
  • Add "slow" to almost everything — slow moves hide what the model can't render; fast moves expose every flaw.
  • Arcs around people stay under ~30°; products on a pedestal can take a full turn.
  • Handheld needs "subtle" or the model goes full earthquake.
  • Three tracked characters max across cuts — beyond that faces migrate between bodies. (This is exactly the "3+ characters loses likeness" note we already learned the hard way.)
  • Exit-frame means gone. Never exit and re-enter within one continuous take.
  • Compose around mirrors, never into them.
  • Re-establish after every cut — restate positions and facing, keep the camera on one side of the action line.
  • Emotions are physics, not labels: "jaw clenches, nostrils flare," not "looks angry."
  • Action is intent plus a named move, never joint-by-joint biomechanics.
  • Only what can be seen or heard. Smells, thoughts and backstory render as nothing.

6. Audio discipline — end every video prompt with "No music. No subtitles."

Generated music locks you in and burned-in captions can't be removed. We score and caption in the edit, where we control it. If a clip carries dialogue, keep "no subtitles" and let the line live in quotes.

7. Text in the image

Quote every word exactly and say where it goes. Few text elements, one or two sizes. When a word keeps mangling, spell it letter by letter (spelled F, O, C, U, S) in an edit pass — don't re-roll the whole design. Free-form on-screen text in video is unreliable: declare a text-safe zone ("the right third falls to clean darkness") and set type in post.

8. Gear numbers are a weak lever

Focal lengths and apertures barely register across nearly every model. Say the effect instead: "background melts into soft blur," "only the label in focus," "creamy focus roll-off."

Vocabulary shortlist

Stack two or three per prompt, never all — stacked look words dilute each other.

  • Light: shadowplay (most reliable keyword in testing) · single soft key from upper left · hard shaft of light · practical light only · low-key · rim light · golden hour
  • Grade & mood: muted palette · faded blacks · gentle contrast · cinematic · editorial · quiet-luxury · understated
  • Texture: fine uniform film grain · visible pores · tactile fabric weave · atmospheric haze · soft highlight bloom
  • Composition: generous negative space · centered, deadpan framing · chest-up crop · slight three-quarter angle · leading lines
  • Blur/focus: background melts into soft blur · creamy focus roll-off · subject razor sharp against a soft distance
  • Tested stacks: shadowplay + cinematic + fine film grain · muted palette + faded blacks + negative space · practical light only + atmospheric haze

Video: Seedance 2.5 = default (30s, 4K, up to 50 refs, native audio) · Kling 3.0 Omni = character continuity, physics, dialogue, on-product text, faithful video-to-video · Happy Horse 1.1 = fast/cheap · Gemini Omni Flash = conversational direction and physics-aware edits, lower quality.

Our Magnific setup uses Nano Banana 2 Flash as the image model, and Kling for lip-sync via its own API — that stays as-is. This table is for deciding which model to reach for, not for changing what's already locked.

Where this handbook does NOT override us

The handbook is general best practice; our project rules are tested on this show. Project rules win.

Two live conflicts to be aware of:

  1. Keyframe prompt tails. Our rule is drop the style/negative boilerplate tail entirely on keyframe prompts. The handbook wants a film-look line and a standard negative set in every prompt. Ours was tested on our comic-book style — keep dropping the tail. The handbook's line is for photoreal work.
  2. Photoreal grade language. The film-look line ("soft cinematic lens… fine uniform film grain… no digital look") is aimed at photorealism. Our show is comic book / graphic novel style. Use the handbook's structural advice (framing, camera moves, scene rules, character sheets, the first-frame pipeline) freely; use its grade language only where we're actually going photoreal.

Also unchanged: the approved Ruby host plates are never regenerated, the logo is baked not composited, and the camera-movement prompt library is still the source for motion wording.
