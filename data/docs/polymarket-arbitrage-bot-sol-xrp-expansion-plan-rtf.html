Code changes (in order of dependency)

BINANCE_SYMBOLS = ["btcusdt", "ethusdt", "solusdt", "xrpusdt"]

Net: Binance subscribes to 4 streams. Chainlink firehose starts recording SOL/XRP frames instead of discarding them.

Also verify the title-parsing regex _ASSET_RE recognizes SOL/XRP. The current regex has only BTC and ETH entries. Add:

"SOL": re.compile(r"\bSolana\b|\bSOL\b", re.I),

Pre-deploy probe: verify these regexes against actual Polymarket market titles. Don't assume the title format – query the Gamma API and inspect a real SOL or XRP market question string first.


Step 3 — strategy.py


Almost certainly no change. market.asset is generic, the dispatcher is asset-agnostic, per-duration edge thresholds apply uniformly.


Caveat: the _STEEPNESS_BY_DURATION constants (k=150 for 5min, k=100 for 15min) are empirically calibrated for BTC/ETH. SOL has roughly 1.5–2x BTC's daily realized volatility; XRP is somewhere in between. Same k would over-react to moves on SOL/XRP – a 0.4% SOL move is much more common than a 0.4% BTC move and shouldn't get the same probability boost.


Calibration options:

• Option A: ship as-is, accept over-firing for a few days, observe signal density and outcomes, then add per-asset k values. Recommended – empirical first.

• Option B: pre-calibrate by checking SOL/XRP historical vol vs BTC and dampening k proportionally. Replace _STEEPNESS_BY_DURATION with a _STEEPNESS_BY_ASSET_DURATION dict.


Step 4 — bot.py


The STATUS print loop already iterates config.BINANCE_SYMBOLS. It'll auto-pick up SOL/XRP. The feed_status() line in price_feed.py also iterates the symbol map. No code changes needed – just longer log output. 4 assets x 2 feeds = 8 fields might wrap on narrow terminals. Acceptable cost.


Step 5 — cross-asset correlation guard (risk_manager.py + bot.py)


Currently bot.py has a guard: if BTC UP 5min is open, block ETH UP 5min on the same Binance move. With 4 assets, this needs a design call:


• BTC UP + ETH UP same window – block ETH (current behavior)

• BTC UP + SOL UP same window – ??? (SOL is highly correlated with BTC/ETH)

• ETH UP + SOL UP – ??? (very correlated)

• BTC UP + XRP UP – ??? (less correlated than the others)


Three policies to choose between:

• (a) Conservative: continue blocking same-direction across all 4. May miss diversified trades.

• (b) Middle ground: block only within tight asset pairs (BTC<->ETH, SOL<->XRP), allow BTC+SOL.

• (c) Aggressive: drop cross-asset blocking entirely, rely on MAX_OPEN_POSITIONS only.


Recommended: ship (c) initially – per-asset+direction+duration uniqueness only, no cross-asset blocking. Observe whether SOL/XRP + BTC/ETH same-direction races produce duplicate-exposure losses. Add correlation-aware blocking only if it does.


Validation steps (before going live on SOL/XRP)


1. Probe Polymarket market titles for SOL and XRP to verify the _ASSET_RE regex matches the displayed question text (not the slug).

2. Verify Chainlink delivers sol/usd and xrp/usd continuously (we caught one sol/usd sample in the May 11 probe – confirm freshness over time).

3. Verify Binance WS handles 4 symbol streams without rate-limit issues. Should be fine but worth checking.

4. Depth check on SOL/XRP markets at the typical bot order size ($12.52 USDC). Polymarket book depth for SOL/XRP markets is typically thinner than BTC/ETH – FAK fills should still work for that size, but a $50+ order may hit the no-liquidity wall faster.

5. Monitor the first hour after deploy for: signal density (expect 2–3x more), order success rate (FAK should still hit on SOL/XRP), unexpected errors.


Risk profile


• Increased exposure: if you trade SOL UP and BTC UP at the same time on the same Binance move, you're 2x exposed to the same underlying signal. Same as today's BTC+ETH problem but multiplied across more pairs.

• SOL/XRP liquidity: Polymarket book depth for SOL/XRP markets is typically thinner than BTC/ETH.

• Calibration risk: signals will likely over-fire on SOL/XRP at current _STEEPNESS_BY_DURATION = 150. May lose money on noisy small-move signals until calibrated.


Rollback plan


If signal density is overwhelming or losses spike: revert _SLUG_PREFIX to BTC/ETH only. Single commit revert. Binance and Chainlink subscriptions can stay at 4-symbol – the unused data just gets ignored.
