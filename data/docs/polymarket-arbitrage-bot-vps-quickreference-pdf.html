Daily Monitoring (no SSH normally needed)
The bot pushes everything you need to Telegram and the browser dashboard. You should not need to SSH in just to check on
it.

Heartbeat (Telegram)

Silent message every 30 minutes. Format: [LIVE] Balance: $X | PnL: +N.NN (N.N%) | Pos: N | Feed: BTC BN:Xs CL:Ys | ETH
BN:Xs CL:Ys. If no heartbeat for 60+ minutes, the bot is likely down — SSH in and check the container.

Trade alerts (Telegram)

On every signal/fill/error/crash. Format: SIGNAL[SRC] | ASSET DIR Nmin | edge=N% ... where SRC is BINANCE or
CHAINLINK.

Deploy a Code Change
Source is git-managed. NEVER scp source files directly to /opt/polymarket-bot/ — git pull overwrites them.

On your Mac:
cd /Users/rubys/Desktop/AI_bots/Polymarket-Arbitrage-Bot
git add <file>
git commit -m "describe change"
git push origin main

On the VPS (one-liner):
ssh poly-vilnius "cd /opt/polymarket-bot && git pull && docker compose build polymarket-bot && docker
compose up -d polymarket-bot"

Never use --force-recreate — Docker network namespace teardown breaks the Binance WS handshake. Plain docker
compose up -d picks up the new image correctly.

Troubleshooting
     No heartbeat for 60+ min        Bot likely down. Run: ssh poly-vilnius 'docker compose ps' — if
                                     Exited, check logs.

     CL:stale persistent            Polymarket Chainlink RTDS broadcasts sparsely — likely normal. Binance path still
                                    works.

     403 in logs                     Geo-block returned. Run: ssh poly-vilnius 'curl -s ipinfo.io' to
                                     confirm country is LT.

     Binance WS disconnect          Auto-reconnects with exponential backoff up to 60s. Persistent means network issue.

     Container exited                ssh poly-vilnius 'docker compose logs --tail=100 polymarket-bot' —
                                     look for traceback.

     Pre-commit hook fails          Fix the underlying issue. NEVER bypass with --no-verify.



Critical Rules (so we don't repeat 2026-05-10 mistakes)
1. NEVER scp source files directly to /opt/polymarket-bot/ on the VPS — git is the source of truth; scp'd files get overwritten
on next pull.
2. NEVER use docker compose --force-recreate — breaks the Binance WS startup.

3. VERIFY live state before asserting facts — check the actual running container, actual config, actual IP. Stale docs are a
known failure mode.

4. Only one bot per Polymarket wallet at any time — parallel instances on the same wallet cause double-trades.

5. Don't force push to main — this is a solo project so there's no PR review; treat git push with the seriousness it would have
in a team.
