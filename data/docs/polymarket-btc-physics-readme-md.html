Bitcoin Market Physics — Polymarket data & analysis (v1)

A small tool that treats Bitcoin as a physics problem instead of a charting problem, following the approach in @Gustafssonkotte's article "How I Learned to Read Bitcoin Through Thirty Thousand Data Points."

This version only watches and measures. It does not trade, and it cannot move money — every data source is public and read-only. The point is to first prove, on today's market, the same "physics" the author measured, before any strategy or real funds are involved (his own warning: small samples deceive, simulations overstate).

What it measures

Every ~2 seconds it records one snapshot:

ThingPlain meaning
speed ($/min)How fast Bitcoin is moving right now — dollars per minute.
bandThe "weather": quiet / normal / active / storm / hurricane.
distance ($)How far Bitcoin is above/below the price the market window opened at (the strike).
time to closeSeconds left in the current Polymarket window.
Up / Down priceWhat Polymarket is charging for the "Up" and "Down" outcomes.

It follows Polymarket's Bitcoin Up or Down market (15-minute window by default; 5-minute is a config switch). Bitcoin price comes from Coinbase spot.

Accuracy note: Polymarket settles these markets on the Chainlink BTC/USD feed; we read Coinbase spot. They track closely but not to the cent, so "distance from strike" is a faithful proxy, not the exact settlement figure.

Setup

pip install -r requirements.txt

Use

1. Collect data (leave it running — minutes for a taste, days to match the article):

python collector.py

Stop any time with Ctrl-C. Data accumulates in data/snapshots.db.

2. See the results — reproduces the article's tables and saves two charts:

python analyze.py

Prints speed median/mean, the weather-band breakdown (% of time), average speed by UTC hour (look for the volatility jump around the 14:00 UTC US open), and distance-from-strike stats. Charts land in data/.

Tuning

All knobs live in config.py: snapshot cadence, the speed-measuring window, 5- vs 15-minute market, and the speed-band edges.

Running on a VPS with Docker

The collector is built to run continuously on a server. Files: Dockerfile, docker-compose.yml. Collected data is stored on the host (./data), so it survives rebuilds and restarts. The container auto-restarts (unless-stopped).

First-time deploy (Docker + Compose already installed):

git clone <repo>           # private repo: uses a read-only deploy key
cd polymarket-btc-physics
docker compose up -d --build

Day-to-day (run these against the server, e.g. ssh poly-vilnius '...'):

docker compose logs -f                      # watch live snapshots
docker compose exec collector python analyze.py   # print tables + write charts to data/
docker compose down                         # stop the collector
git pull && docker compose up -d --build    # update after a code change

Charts land in the server's data/; copy them to your laptop with scp <host>:~/polymarket-btc-physics/data/*.png .

What's intentionally not here yet

  • A paper-trading engine (simulated fills on the recorded token prices).
  • The decision logic: the physics-vs-token-price gap and the WEAK_COMBO

filter (skip a trade when both signals are weak). The article deliberately withholds its thresholds — those get tuned on our data later.

  • Any live trading. That stays off until paper results justify it.

Layout

collector.py   the 2-second snapshot loop
analyze.py     reproduce the article's tables + charts
feeds.py       Coinbase price + Polymarket market lookup (read-only)
metrics.py     pure math: speed, distance, time-to-close, band
storage.py     SQLite read/write
config.py      all the knobs
tests/         unit tests for the math
