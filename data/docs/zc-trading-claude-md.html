Rules

1. Verify before handing back. Never hand Eddie QA. Run the check, report the number. pytest -q output, the coverage figure, the actual backtest result. "Should work" is not verification.

2. Name your source. "The backtest shows X" — not "X is true."

3. Live state beats written claims, including this file. This file said "Planning/Foundation Phase" long after src/, tests/, config/ and a .venv existed. Check the tree before describing the project's state.

4. Never implement fully autonomous execution. Every trade requires human confirmation. The system identifies setups, sizes them, and presents them for approval — it does not place orders on its own. Psychological readiness cannot be automated.

5. No curve-fitting. Forbidden: look-ahead bias, over-fitting to one market period, rules written for specific recent trades, rule changes triggered by a single loss, rules added to explain away a weakness. Changes must improve out-of-sample performance.

6. Every function gets a test. pytest, target 85% coverage, happy path and error cases. Don't integrate untested code.

7. Validate data before any execution path runs. OHLC current within 30s, price cross-checked across sources where possible, S/R levels consistent, position size matches the risk rules.

8. Don't build what isn't in the plan. Check AUTOMATED_TRADING_SYSTEM_PLAN.md before adding a feature. Start simple; add complexity only after a backtest proves it's needed.

9. Scope discipline. No refactoring, renaming, or cleanup that wasn't asked for. Don't average two existing patterns — pick one.

10. Never write files with shell heredocs. Use the Write/Edit tools. A heredoc wrote a literal EOF and a raw cat command into this file and it went unnoticed for months.

11. Ask when trading intent is unclear. Momentum or reversion? Which dimension does it serve? Has it been backtested, and at what accuracy/R:R? Does it need trader confirmation?

12. Deliverables only. Delete generator scripts and scratch files before saying done.

The framework in one screen

Three dimensions — weakness in any one prevents scaling.

DimensionCovers
StrategyJournal, edge development, asset selection
RiskSizing, stop/target placement, scaling
PsychePsychology, routines, discipline under pressure

Two strategies, chosen by environment:

Momentum (breakout)Mean reversion
HypothesisStrength continuesPrice reverts to average
ActionBuy above resistance / sell below supportShort spikes into resistance / long dumps into support
EnvironmentStrong trend, volumeRange-bound, choppy
VWAP signalPrice above VWAP, steep slopePrice choppy around VWAP, flat slope

VWAP is the volume-weighted price anchor: position vs. VWAP = direction, slope = strength, band width = volatility.

Entry criteria

MOMENTUM                            MEAN REVERSION
✓ Price above VWAP                  ✓ Price choppy around VWAP (within 1σ)
✓ VWAP slope > 10° upward           ✓ Fast spike (>2% in <5 min) into level
✓ Breaking/approaching resistance   ✓ Volume declining on spike (weakness)
✓ Volume > 20-day average           ✓ VWAP slope flat or opposite
✓ R:R ≥ 2:1                         ✓ R:R ≥ 2:1
→ Entry: close above resistance     → Entry: rebound from spike level
→ Stop:  below recent swing low     → Stop:  beyond spike extreme

Risk limits (hard)

Max risk / trade:  1% of account   (never above 2%)
Max risk / day:    2%              → stop trading for the day
Max risk / week:   5%              → stop trading for the week

Position Size = (account × risk%) / (stop distance × pip value)

Move to break-even after 1:1. Never trail a stop into a loss. Size up only after 3 consecutive profitable weeks.

Code standards

Python 3.9+, type hints on every function, PEP 8 via black, Google-style docstrings, 100-char lines, pylint ≥ 8.0, pytest with 85%+ coverage.

Critical errors — stop execution: market data gaps, DB connection loss, API auth failure, balance check failure. Warnings — log and continue: setup quality below threshold, sizing edge cases, signal timing delays. All errors get a timestamp and context; critical ones alert the user.

Validation gate (before any strategy ships)

  1. Historical backtest — 6+ months
  2. Accuracy check vs. manual analysis on the same period (>70% agreement)
  3. Walk-forward on unseen data
  4. Stress test across market regimes
  5. Paper trade — 2 weeks minimum

Pass bar: win rate > 50%, profit factor > 1.8, max drawdown < 15%, R:R ≥ 2:1. 6-month targets: win rate 55%+, profit factor 1.8+, monthly return 5–10%, drawdown <15%, setup accuracy 75%+, execution <200ms, logging 100%.

Start simple. Validate. Iterate. Only add complexity that backtests prove valuable.
