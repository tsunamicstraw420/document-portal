Decision: GitHub now, Hetzner later

Decided: 2026-05-16 Status: Active

What we chose

  • Create the GitHub repo immediately and push the planning docs + Phase 1 skeleton.
  • Defer Hetzner VPS, Docker compose, Postgres, InfluxDB, Redis until Phase 4 (Weeks 10-12 in AUTOMATED_TRADING_SYSTEM_PLAN.md) — i.e. when there is something always-on to run.

Why

  1. Phase 1 doesn't need always-on. The first ~6 weeks of work (VWAP, S/R detection, spike detection, position sizing) is pure backtesting on historical CSVs. That runs perfectly on the Mac and doesn't care if the Mac sleeps overnight.
  2. Premature infra violates our own rule. CLAUDE.md says "start simple, validate, iterate." Spinning up a 3-database VPS before any code uses it is yak-shaving.
  3. GitHub is cheap and high-value now. Every commit needs a remote home; we'd be doing this eventually regardless.
  4. Decisions deferred are decisions improved. By the time we hit Phase 4 we'll know which databases we actually need based on real workloads — not guesses from the planning doc.

What "always-on" actually requires (so we know it when we see it)

We need the VPS when any of these is true:

  • We're consuming a live WebSocket feed (TradingView / exchange) 24/7
  • We're running scheduled jobs (nightly backtest refresh, weekly performance report)
  • We're sending real-time alerts to the trader (SMS/email) that must fire when the Mac is off
  • We're placing real orders that need to survive client crashes

None of those is true today. All become true around Phase 4.

Open questions (decide before Phase 4)

1. Postgres-on-Hetzner as middle ground?

If the Mac going to sleep starts losing data (e.g. partial backtest runs, journal entries), one cheap middle step is:

LayerWhere
Dev loopMac (unchanged)
GitHubunchanged
Postgres (trade log only)Hetzner Docker — survives Mac sleep
InfluxDB, Redis, live runnerStill deferred

A single small Postgres container on a Hetzner CX22 (~€5/mo, 4 GB RAM) is ~30 min of setup. Defer unless the pain shows up.

2. Secrets management

Before any exchange API keys go anywhere, decide:

  • Option A: .env file gitignored locally (fine for paper trading)
  • Option B: pass / 1Password CLI integration (better for production)
  • Option C: Hetzner-side secret in env file mounted to container (production)

Don't ship real keys until this is settled. For now: no real keys anywhere.

3. Backups

When we have a trade log worth losing:

  • Daily pg_dump off the VPS to local storage or a third-party (Backblaze B2, etc.)
  • Encrypted at rest
  • Retention: 90 days minimum

Decide before Phase 4.

4. Hetzner region

When we get there: Falkenstein (Germany) or Helsinki (Finland) are the cheapest. For US-based exchanges, US regions or AWS would be lower latency — but the strategies in scope (1-min altcoin trades, not HFT) don't need sub-100ms latency. Hetzner EU is fine.
